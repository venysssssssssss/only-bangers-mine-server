# Relato de vulnerabilidades

Não publique segredos, provas de conceito exploráveis ou detalhes sensíveis em
issues, pull requests ou discussões públicas.

Quando o repositório estiver habilitado para isso, use um **GitHub Security
Advisory** privado para enviar o relato. Se essa opção não estiver disponível,
contate o mantenedor por um canal privado listado no perfil ou na página do
repositório e informe:

- componente afetado e versão/commit;
- passos mínimos para reproduzir;
- impacto observado;
- correção sugerida, se houver;
- se algum segredo já foi exposto, quais credenciais devem ser revogadas.

O mantenedor deve confirmar o recebimento, avaliar impacto e combinar a
divulgação pública somente depois de existir uma correção ou mitigação. O
projeto não garante um SLA de resposta, mas relatos privados têm prioridade
sobre discussões públicas.

Se você expôs um token ou senha, revogue-o primeiro. Apagar o arquivo depois
não remove cópias que já chegaram ao histórico ou a clones de terceiros.
